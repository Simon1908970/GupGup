# K-컬처 — 국가별 현지 언론의 한국 관련 보도

취지: 한국 엔터테인먼트 매체(Soompi·Koreaboo 등 한국발 정보)가 아니라, 줍줍이 다루는 9개 국가의
**현지 언론**이 한국을 어떻게 보도하는지를 모은다. **2개 범주를 각각 찾는다** — (A) 외교·경제·
사회·여행·교육 등 **일반 한국 관련 뉴스**, (B) **K-pop·K-drama** 등 한류 콘텐츠 보도. 둘 다
"한국 관련 기사와 kpop, kdrama 관련 내용"이라는 사용자 원 요청에 명시된 별개 범주다 —
K-pop/K-drama만 모으고 (A)를 빠뜨리면 안 된다(2026-10-28 1회차에서 이 실수를 했다가
사용자 지적으로 바로잡음).

> **2026-10-28 전면 개편 (사용자 요청).** 기존에는 Soompi·Koreaboo 등 한국(발) 매체를 Exa/RSS로
> 자동 수집하는 `fetch-kculture.mjs` 스크립트가 있었으나, 사용자가 "한국 기사·정보가 아니라
> 각국 뉴스 사이트에서 한국 관련 기사를 모아달라"고 요청해 전면 재설계했다. 기존 스크립트·
> 테스트·`sources.json`·예약 실행 스크립트(`run-fetch-kculture.ps1`)는 모두 삭제했다 — 이제
> 이 기능은 (국가별 SNS 리서치와 마찬가지로) 예약 자동 수집 없이, 매번 Claude가 라이브로 웹
> 검색·기사 열람을 수행하는 세션 기반 작업이다. (참고로 직전까지 있었던 "한국인과의 연애 후기"
> 섹션은 이보다 하루 전인 2026-10-27에 이미 별도로 제거됐다.)

## 수집 난이도 메모 (2026-10-28 1회차 경험 — 다음 회차 참고용)
현지어 뉴스 사이트는 한국 엔터테인먼트 전문지가 아니라서, 매 회차 9개국 모두에서 "이번 주"
수준의 신선한 기사가 나오지는 않는다. 1회차 실제 결과:
- **베트남·태국·인도네시아·필리핀**: 최근 1~2주 내 기사를 각 1건씩 비교적 수월하게 확보.
- **몽골·캄보디아·기타(중앙아시아)**: "한국" 전용 태그/섹션은 있으나(news.mn `/sedev/k-pop/`
  등) 최신 글이 수개월 전인 경우가 많았음 — 이럴 땐 날짜를 숨기지 말고 "몇 달 전 기사지만"
  이라고 솔직히 밝히고 쓴다. 날짜 안 맞는 걸 숨기는 것보다, 오래됐어도 진짜 현지 기사를
  쓰는 쪽이 낫다. 캄보디아는 추가로 Khmer Times가 Cloudflare 봇 차단에 막혀(r.jina.ai·
  Claude Browser 둘 다 실패) Phnom Penh Post로 대체했다 — 다음 회차에 Khmer Times를
  다시 시도해볼 것.
- **미얀마**: 일반 뉴스에서 K-pop/K-drama 자체 보도가 거의 없었음. 정부·대사관 공지(Changwon
  K-Pop World Festival 현지 예선 응모 등)로 대체 가능 — 언론 기사는 아니지만 현지에서 실제
  벌어지는 한국 관련 소식이라 유효하다고 판단.
- **라오스**: 라오어 엔터테인먼트 매체 자체가 희박해 1회차는 수확이 없었음 — 억지로 무관한
  내용을 끼워 넣지 말고 "이번 회차 수집 없음"으로 정직하게 기록했다.
- Khaosod(태국)처럼 일부 사이트는 `r.jina.ai` 변환 결과가 광고·메뉴만 잡고 본문을 놓치는
  경우가 있었음 — 이럴 땐 Claude Browser로 직접 열어 `get_page_text`로 읽는다(아래 절차
  3번 참고).

## 요약 요청 시 절차 (Claude용)
1. 국가 9개 각각에 대해, (A) 일반 한국 관련 뉴스와 (B) K-pop/K-drama를 **따로따로** 검색한다
   — 그 나라 언어(필요시 영어 보조)로 (A)는 "한국"/"대사관"/"무역"/"유학" 류, (B)는
   "K-pop"/"K-drama"/그 나라 언어의 "한국 드라마" 류 키워드를 WebSearch로 검색한다. 위 표의
   매체 도메인으로 `allowed_domains`를 좁히면 무관한 결과를 크게 줄일 수 있다. 결과가
   부실하면 그 매체의 전용 섹션/태그 페이지(예: `detik.com/pop/korean-wave`,
   `news.mn/sedev/k-pop/`, `gmanetwork.com/entertainment/tag/korean_news/`,
   `thairath.co.th/tags/KPOP`, 각 매체의 "세계"/"외교" 섹션)를 Claude Browser로 직접 열어
   최신 목록을 확인하는 편이 검색보다 나을 때가 많다.
2. 국가당 (A) 1~2건 + (B) 1~2건을 고른다 — 실제 그 언론사 기사인지, 한국과 명확히 관련
   있는지 확인한다. 날짜가 오래됐으면(수개월 전) 숨기지 말고 그대로 밝힌다. 한 범주에서
   끝내 아무것도 못 찾으면 억지로 채우지 말고 그 범주만 "수집 없음"이라고 쓴다(다른 범주는
   있으면 그대로 싣는다 — 둘 다 없을 때만 국가 전체를 "수집 없음"으로 비운다).
3. 후보 기사 원문을 `curl -s "https://r.jina.ai/<link>"`로 읽는다. r.jina.ai가 광고·메뉴만
   가져오고 본문을 못 가져오면(JS 렌더링 사이트에서 종종 발생, Cloudflare 봇 차단에 막히면
   더더욱) Claude Browser로 그 URL을 직접 열어 `get_page_text`로 읽는다.
4. 각 기사마다 다음 형식으로 작성:
   - **원문 발췌**: 기사 핵심 2~4문장만, 원문 언어 그대로, 700자 이내(전문 복사 금지).
   - **한국어 요약**: 2~4문장, 자기 표현으로 재작성(기계번역 아님, 사실관계만 정리).
   - **출처**: 매체명 + 보도일 + 원문 링크 필수.
5. `kculture/<날짜>.md`에 국가별 섹션(9개, 고정 순서: 베트남 → 태국 → 라오스 → 인도네시아 →
   미얀마 → 필리핀 → 몽골 → 캄보디아 → 기타)으로 정리하되, 각 국가 섹션 안을 다시
   "한국 관련 뉴스"/"K-pop·K-drama" 두 하위 묶음으로 나눈다(`TEMPLATE.md` 형식 참고).
6. **로컬 전용**: git add / commit / push 하지 않는다.
7. 대화창에 국가별 하이라이트만 짧게 보고(파일 전체를 다시 붙여넣지 않는다). 수집 없음으로
   끝난 범주/국가가 있으면 그것도 짧게 언급.

## SNS 직접 브라우징 (Claude in Chrome)

이 섹션은 위 "국가별 현지 언론 보도 수집" 절차와는 **별개의 기능**이다(2026-10-28 전면
개편 때도 이 섹션은 그대로 유지 — 혼동하지 말 것). "K컬처와 SNS를 요약해줘" / "SNS도
같이" 처럼 **SNS를 명시적으로 언급했을 때만** 위 절차에 더해 수행한다 (plain "K컬처
요약해줘"에는 포함 안 함 — 매번 사용자 계정으로 실제 브라우징하는 무거운 작업이라서).
위 현지 언론 보도 수집과 마찬가지로 **자동/예약 실행이 아니다** — Claude in Chrome으로
사용자의 이미 로그인된 크롬 세션에 매번 직접 들어가서 진행해야 한다.

### 원칙
- **플랫폼**: Facebook, Instagram, TikTok. 각각 로그인 여부를 먼저 확인하고(로그인 안
  되어 있으면 건너뛰고 사용자에게 알림), 로그인은 절대 대신 하지 않는다(비밀번호 입력 금지).
- **읽기·검색만 한다.** 좋아요·팔로우·댓글·DM·친구 요청 등 계정으로 수행하는 액션은
  사용자가 명시적으로 요청하지 않는 한 하지 않는다 (친구 요청 대량 자동 발송은 플랫폼
  이용정책 위반 소지 + 계정 정지 위험이 있어 애초에 하지 않음 — 후보 프로필만 정리해서
  사용자가 직접 보내도록 안내).
- **대상 범위 한정**: 게시물의 출처 또는 대상이 ① 한국 거주자이거나 ② 줍줍이 실제 쓰는
  8개 국가 — 베트남·태국·라오스·인도네시아·미얀마·필리핀·몽골·기타(중앙아시아 등) —
  중 하나여야 함. (2026-10-15 개편: 말레이시아·캄보디아·싱가포르·브루나이를 포함하던
  아세안 10개국 범위는 폐기하고 이 8개국으로 통일했다 — 하단 "국가별 SNS 리서치" 참고.
  **주의**: 위쪽 "국가별 현지 언론 보도 수집" 절차는 2026-10-28에 캄보디아를 추가해 9개국
  체계지만, 이 SNS 리서치 레이어는 아직 8개국 그대로다 — 사용자가 이쪽도 캄보디아 추가를
  원하면 `countries/_lib.mjs`의 `COUNTRIES`·`countries/rotation.json`·
  `countries/keywords.md`까지 같이 손봐야 한다.)
- **계정 보호**: 자동화 탐지를 피하려고 매 액션 사이 간격을 불규칙하게 두고 천천히
  진행한다. 검색은 플랫폼당 2~3개 정도로 가볍게 끝내고, 무리하게 많이 긁지 않는다. 다만
  아래 "주제 2갈래"의 두 하위 주제(거주/비자 vs 유학생/장학금·TOPIK)는 서로 다른 커뮤니티라
  한쪽만 검색하면 다른 쪽이 통째로 빠지므로, 매 라운드 각각 최소 1개씩은 검색어를 바꿔가며
  확인한다 (2026-10-16 태국 라운드에서 거주/비자 키워드만 검색하고 유학생/TOPIK 쪽을
  빠뜨렸다가 사용자가 지적해 추가 검색으로 보완한 사례 있음 — 이후 라운드부터는 처음부터
  포함). 플랫폼이 자동으로 띄우는 팝업(프로필 완성 유도 등)은 아무 값도 입력하지 않고
  취소로 닫는다.
- **주제 2갈래, 실은 4갈래 (2026-10-15 개편, 2026-10-16 보강 x2)**: 실용정보는 다시 (1a) 거주·
  비자·서류(외국인등록증 등) 커뮤니티, (1b) 유학생·장학금·TOPIK/한국어 공부·한국 대학 생활
  (동아리, 말하기대회, 학교 졸업 등) 개인 콘텐츠, (1c) **한국 유학원(에이전시)** — 그 나라
  학생을 한국 유학으로 보내주는 걸 업으로 하는 정식 업체/페이지로 나뉘고, 여기에 (2) 한국인과의
  연애·국제커플 및 K-pop/K-drama에 대한 위 국가들의 반응이 더해져 사실상 네 갈래다.
  (1c)는 (1b)와 검색어가 또 다르다 — "유학생"/"TOPIK" 같은 커뮤니티·개인용 키워드로는 거의
  안 걸리고, 그 나라 말로 "유학 상담센터/에이전시 + 한국"류 비즈니스 용어로 검색해야 페이지
  탭(FB)·계정 바이오(IG·틱톡)에 뜬다 (2026-10-16 태국 라운드: "ศูนย์แนะแนวเรียนต่อเกาหลี"로
  검색해서야 팔로워 2.4만의 정식 유학원 페이지를 찾음 — "นักเรียนไทยในเกาหลี" 같은 커뮤니티
  키워드로는 안 나왔었음). `keywords.md`의 "실용정보" 섹션 검색어에 이 세 계열이 섞여 있으니,
  라운드마다 (1a)(1b)(1c) 각각 최소 1개씩은 검색어를 바꿔가며 확인할 것. 국가별 검색어는
  `countries/keywords.md`에 정리되어 있다 — 하단 "국가별 SNS 리서치" 참고.
- **TikTok 인기 Top 10("한국" 검색) — 2026-10-26 추가**: 그 나라 언어로 "한국" 한 단어만
  검색해 좋아요 수 기준 상위 10개를 뽑고, 이전 라운드와 중복되면 다음 순위로 채운다. 자세한
  절차는 `countries/README.md` 참고(이 README의 요약판이 아니라 그쪽이 최신 원본).
- **랭킹은 "대략"이면 충분** — 정확한 조회수 집계가 아니라 검색 중 발견한 것 중 눈에 띄는
  것 위주로 10개 안팍 정리. 틱톡은 "인기" 정렬 탭에 좋아요 수가 보여 비교적 정확하고,
  페이스북은 피드에 수치가 잘 안 보여서 노출 순서로만 가늠한다.
- **링크 수집**: 가능하면 각 항목의 실제 게시물 URL을 받아와 기록한다(다음 회차에서
  빠뜨렸다면 다음 회차엔 꼭 챙길 것 — 링크 없는 "제목+수치"만으로는 사후 검증이 안 됨).
  URL을 못 받아온 항목은 국가별 파일에 "(⚠️ 링크 미확보)"로 표시되고, URL이 없어 같은
  글인지 판단할 수 없으므로 중복억제 대상에서도 빠진다 — 다음 회차에 다시 걸려도 또 올라갈
  수 있다는 뜻.
- **결과 반영 (2026-10-15 개편)**: `kculture/<날짜>.md`가 아니라 `countries/<code>.md`
  (국가별 누적 파일)에 반영한다 — 하단 "국가별 SNS 리서치" 참고. 로컬 전용(git 커밋 안 함)은
  동일하게 적용.

### 국가별 SNS 리서치 (2026-10-15 개편)
아세안 10개국을 라운드당 2개국씩 돌던 방식은 폐기했다. 대신 줍줍이 실제 쓰는 8개
국가(베트남/태국/라오스/인도네시아/미얀마/필리핀/몽골/기타)를 라운드당 1개국씩 돌면서,
연애·팬덤뿐 아니라 비자·서류·장학금 등 실용정보까지 같이 찾아 국가별 파일에 누적하는
방식으로 바뀌었다. 절차는 `countries/README.md`, 검색어는 `countries/keywords.md`,
로테이션 상태는 `countries/rotation.json` 참고. 2026-10-14에 옛 방식으로 수집한
베트남·필리핀 내용(연애·팬덤만)은 이 `kculture/2026-10-14.md`에 그대로 남아있다 —
새 국가별 파일로 옮기지 않았다.

## 편집 규칙
- 루머·미확인·낚시성 제외. 열애설·해체설 등은 공식 확인된 것만.
- 원문 전문 복사 금지 — 발췌(2~4문장, 700자) + 한국어 재작성 요약 + 링크만.
- 광고·협찬·명백한 개인 홍보 제외.
- 국제연애·커플 관련 콘텐츠가 섞여 들어오면(SNS 국가별 리서치의 "연애·팬덤" 섹션과 겹치는
  주제라 이 파이프라인에서는 흔치 않지만): 개인 식별정보(닉네임·구체 신상·사진) 제거, 주제
  단위로 묶어 요약, 대표 출처 링크만 남긴다.

## 자동화 없음
이 기능은 스크립트·예약 작업이 없다 — 매번 Claude가 라이브로 수행한다(국가별 SNS 리서치와
동일한 모델). `news-digest/fetch-kculture.mjs` · `fetch-kculture.test.mjs` ·
`kculture/sources.json` · `run-fetch-kculture.ps1`은 2026-10-28에 모두 삭제했다(참고로 당시
Windows 작업 스케줄러에는 이 스크립트를 실행하는 등록된 작업이 없었음 — 확인 후 삭제).

## 60일 정리 (이제 수동)
`kculture/` 안의 날짜형 `<YYYY-MM-DD>.md` 중 오늘 KST 기준 60일보다 오래된 것을, 요약 요청을
받을 때마다 Claude가 직접 확인해 삭제한다. (예전에는 `fetch-kculture.mjs`가 실행될 때마다
자동으로 정리했으나, 그 스크립트가 삭제되면서 지금은 수동 절차다 — 요약 요청이 뜸하면 그만큼
정리도 늦어질 수 있음.)
