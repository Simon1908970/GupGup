# K컬처 — 국가별 SNS 리서치 레이어 설계 문서

- 날짜: 2026-10-15
- 상태: 설계 승인됨 (구현 계획 대기)
- 관련: [2026-08-29-kculture-weekly-digest-design.md](2026-08-29-kculture-weekly-digest-design.md) (기존 주간 다이제스트, 변경 없음),
  `news-digest/kculture/README.md`, `news-digest/kculture/sources.json`, `news-digest/keywords.md`

## 배경 / 목적

K컬처 파이프라인은 지금 두 축으로 돈다: (1) `fetch-kculture.mjs`가 Exa/RSS로 주 1회 자동
수집하는 영어 위주 주간 다이제스트, (2) 사용자가 "SNS도 같이"를 명시했을 때만 Claude in
Chrome으로 사용자의 로그인 세션에 들어가 페이스북·인스타·틱톡을 직접 브라우징하는 수동
단계 — 이 수동 단계는 지금까지 "아세안 10개국을 라운드당 2개국씩 돈다"는 임시 로테이션으로
운영됐고, 2026-10-14에 베트남·필리핀만 끝낸 상태다.

이 문서는 그 수동 SNS 단계를 다음과 같이 재설계한다:

1. **대상을 아세안 10개국 → 줍줍이 실제 쓰는 8개 국가 필터로 교체.**
2. **다루는 내용을 연애·팬덤 단일 축에서, 일반 뉴스 파이프라인(`keywords.md`)의 비자·서류·
   장학금·유학생 등 실용정보 축을 더해 2축으로 확대.** (일반 뉴스 파이프라인 자체는 건드리지
   않음 — 그 키워드를 "번역해서 SNS에서도 찾아본다"는 것뿐.)
3. **결과를 날짜가 아니라 국가 단위로 누적 저장**하고, 줍줍 뷰어에서 국가별로 바로 찾아볼 수
   있게 한다.

주간 다이제스트(Exa/RSS/Reddit, 날짜 파일)는 이 문서의 범위 밖이며 그대로 유지된다.

## 범위

**포함**
- 신규 "국가별 SNS 리서치" 서브 레이어 (K컬처 파이프라인 내부)
- 8개국 로테이션(라운드당 1개국), 누적 저장 + 중복 억제
- `news-digest/kculture/countries/` 디렉터리 신규 생성
- 줍줍 뷰어의 K컬처 탭 내부에 "국가별 리서치" 섹션 추가
- `news-digest/kculture/README.md`의 기존 "아세안 국가 커버리지" 절차를 이 설계로 교체

**제외 (의도적으로 손대지 않음)**
- 일반 뉴스 파이프라인(`news-digest/keywords.md`, `fetch.mjs`, 네이버 검색) — 무변경
- 기존 Exa/RSS/Reddit 자동 주간 다이제스트(`kculture/<날짜>.md`, `fetch-kculture.mjs`) — 무변경
- 플랫폼에 "거주지=한국 AND 사용언어=X"처럼 계정을 필터링하는 기능은 틱톡·인스타·페이스북
  어디에도 없음(광고주 전용 타겟팅 도구로만 존재, 일반 검색에는 노출되지 않음) — 이 설계는
  그 기능을 흉내 내지 않고, 대신 "나는 한국에 사는 OO인"이라고 스스로 밝히는 계정/해시태그/
  유학생 키워드로 접근한다.

## 대상 8개국 · 언어 매핑

CLAUDE.md의 국가 필터 목록을 그대로 쓰되, 영어(en)는 필리핀에 합친다(필리핀은 영어가
공용어라 tl/en 둘 다로 검색).

| 국가 | 언어 코드 |
|---|---|
| 베트남 | vi |
| 태국 | th |
| 라오스 | lo |
| 인도네시아 | id |
| 미얀마 | my |
| 필리핀 | tl + en |
| 몽골 | mn |
| 기타(중앙아시아 등) | ru |

## 파일 구조

```
news-digest/kculture/countries/
  README.md       — 절차 설명 (로테이션 방식, 트리거 문구, 계정 보호 원칙 — 기존 kculture/README.md의
                      "SNS 직접 브라우징" 섹션을 대체)
  keywords.md       — 8개국 언어별 검색어 참고 목록 (아래 "검색어 설계" 참고)
  rotation.json      — 다음 차례 국가 추적
  seen.json          — 이미 기록한 게시물 URL (국가별, 중복 추가 방지)
  vi.md, th.md, lo.md, id.md, my.md, tl.md, mn.md, ru.md  — 국가별 누적 결과 파일
```

`rotation.json` 스키마 (예시):
```json
{
  "order": ["vi", "th", "lo", "id", "my", "tl", "mn", "ru"],
  "nextIndex": 0,
  "history": [
    { "country": "vi", "date": "2026-10-20" }
  ]
}
```

`seen.json` 스키마 (예시):
```json
{
  "vi": { "https://www.tiktok.com/@abc/video/123": "2026-10-20" }
}
```

## 국가 파일 형식 (누적)

날짜 기준이 아니라 **국가 기준으로 파일 하나**, 라운드마다 그 안에 새 날짜 섹션을 추가한다
(기존 섹션은 지우지 않음). 중복 억제는 "같은 URL/게시물은 다시 추가하지 않는다"는 단순
1회성 체크로 한다 — 일반 뉴스의 `seen-topics.json`처럼 "같은 토픽을 다루는 다른 기사가
반복되면 카운트로 억제"하는 방식과는 다르다(SNS 게시물은 재검색 시 같은 URL이 그대로
다시 걸리는 게 전형적인 중복이라, 단순 URL 체크가 더 맞는다).

```markdown
# 베트남 — SNS 리서치

## 2026-10-20 수집
### 실용정보 (비자·서류·장학금·유학생 등)
- **제목(한국어 요약)** — 1~2문장 한국어 요약. [출처](URL)

### 연애·팬덤 (K-pop/K-drama 반응, 국제커플)
- **제목(한국어 요약)** — 1~2문장. [출처](URL)

## 2026-11-24 수집 (다음 라운드, 로테이션 한 바퀴 후)
...
```

## 검색어 설계 (`countries/keywords.md`)

국가별로 두 갈래 검색어를 그 나라 언어로 정리(기존 `news-digest/keywords.md`처럼 사람이
자유롭게 고칠 수 있는 참고 목록):

1. **실용정보** — `../../keywords.md`의 비자·서류·장학금·한국어교육 등 카테고리를 번역.
   여기에 **유학생/거주자 식별용 검색어를 별도로 추가**: "<국가명> 유학생"(한국어 그대로도
   검색), 그 나라 언어로 "한국 유학"/"한국 거주" 표현(예: 베트남어 "du học sinh Hàn Quốc",
   "người Việt ở Hàn Quốc"), 그리고 그 커뮤니티가 실제 쓰는 해시태그가 있으면 같이 기록.
2. **연애·팬덤** — `kculture/sources.json`의 K-pop/K-drama/dating 쿼리를 번역.

플랫폼 자체의 "지역+언어 필터"가 없다는 제약은 위 "제외" 항목에 적어뒀고, 이 키워드들이
그 제약을 우회하는 실제 방법이다.

## 기존 데이터 이전

2026-10-14에 옛 방식(아세안 10개국 라운드당 2개국, 연애·팬덤만)으로 수집한 베트남·필리핀
SNS 내용은 `kculture/2026-10-14.md`(주간 다이제스트 날짜 파일) 안에 그대로 남긴다 — 이
설계의 실용정보 축이 없던 결과라 새 국가 파일로 옮기지 않는다. 신규 국가 파일들은 전부
빈 상태(로테이션 1라운드 전)로 시작하고, `rotation.json`의 `nextIndex`는 0(베트남)부터.

## 로테이션 동작

1. `rotation.json`을 읽어 다음 차례 국가를 정한다.
2. `countries/keywords.md`에서 그 나라의 두 축(실용정보/연애·팬덤) 검색어를 가져와, Claude
   in Chrome으로 사용자의 로그인 세션에서 페이스북·인스타·틱톡을 가볍게 검색한다(기존
   kculture/README.md의 계정 보호 원칙 — 검색 2~3개, 액션 없음, 느리게 — 그대로 적용).
3. 찾은 항목을 `seen.json`의 그 나라 URL 목록과 대조해 신규만 골라, 해당 국가 파일에
   새 날짜 섹션으로 append. 한국어 요약 + 원문 링크 형식은 기존과 동일.
4. `seen.json`에 신규 URL 추가, `rotation.json`의 `nextIndex`를 다음 국가로 이동하고
   `history`에 기록.
5. 로컬 전용 — git commit/push 안 함 (기존 kculture 전체 규칙과 동일).

## 줍줍 뷰어 UI 변경

새 최상위 탭을 만들지 않는다. 기존 "K컬처" 탭의 사이드바를 두 그룹으로 나눈다:

- **주간 다이제스트** (기존 동작 그대로 — 날짜 목록)
- **국가별 리서치** (신규) — 8개국 버튼, 각 버튼에 최종 갱신일 배지. 클릭하면 해당 국가의
  누적 파일을 현재와 동일한 마크다운 렌더러로 표시.

`news-digest/viewer/server.mjs`에 국가 목록(파일 존재 여부 + mtime)과 국가별 파일 내용을
읽는 API를 추가한다. 렌더링은 기존 `renderMd()`를 그대로 재사용(이미 `##`/리스트/링크를
처리하므로 국가 파일 형식과 호환됨).

## `kculture/README.md` 변경

기존 "SNS 직접 브라우징 (Claude in Chrome)" 섹션의 "아세안 국가 커버리지 진행 현황"
로테이션 설명을 이 문서의 로테이션(8개국, `countries/rotation.json` 기반)으로 교체한다.
트리거 문구("SNS도 같이")는 유지하되, 동작이 이 설계로 바뀐다는 점을 명시한다.
